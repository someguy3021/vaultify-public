# vaultify

> Русский · [English](../../README.md)

**Общая память ИИ-агентов, общая канбан-доска и мета-управление / полнотекстовый
поиск по нескольким Obsidian vault'ам** — локально, без runtime-зависимостей,
без LLM в ядре.

*На скринах — десктоп-компаньон (русский интерфейс, тёмная тема) на демо-воркспейсе:
пять канбан-колонок, утренний блок подхвата handoff'а и префиксный поиск по
проиндексированным заметкам.*

## Почему

Когда ИИ-агентов у тебя больше одного, память становится инфраструктурой:

- **Проблема амнезии.** У каждого харнесса своя короткая память. Решение, которое
  агент принял во вторник, в среду исчезло — а другой харнесс его вообще не видел.
  Каждая новая сессия выводит контекст с нуля.
- **Проблема рассыпанных знаний.** То, что агенты всё-таки узнали, остаётся в
  логах чатов, а не в твоих заметках. Obsidian-vault'ы, которые ты уже ведёшь —
  канон, которому ты доверяешь, — не получают ничего.
- **Проблема handoff'а.** Передать работу от одного агента (или одного дня)
  другому — руками: скопируй состояние, хвосты, грабли — и надейся, что ничего
  не потерялось.

vaultify отвечает тонким детерминированным слоем между харнессами и vault'ами:
сырая память сессий — в git-мета-репе, дистиллированное знание — записывается
в сами vault'ы, одна канбан-доска и один поиск поверх всего.

## Что внутри

| Область | Команда | Что делает |
|---|---|---|
| Общая память | `vaultify memory save` · `handoff` · `resume` | Сырой append-only слой памяти в git-мета-репе: итоги сессий и структурированные handoff'ы (сделано / осталось / грабли / дальше). `resume` подбирает последний открытый handoff — другой харнесс продолжает там, где остановился первый |
| Доска задач | `vaultify task new` · `board` · `move` … | Один общий канбан поверх SQLite-реестра: `inbox / doing / waiting / someday / done`, приоритеты P0–P3, ссылки на заметки; одними карточками двигаются и человек, и агенты, каждый переход — с причиной |
| Поиск по vault'ам | `vaultify scan` · `search` | Полнотекстовый-подобный поиск по заголовку/тегам/телу всех подключённых vault'ов, плюс задачи и память — префиксный инверт-индекс на `node:sqlite`, осознанно без FTS5, пересобирается `scan`'ом |
| Реестр vault'ов и layout'ы | `vaultify vault add` · `show` · `map` | Регистрирует любую папку с markdown (фокус — Obsidian); layout-профили `strict / flex / single` маппят типы заметок на папки, `flex` авто-детектит существующую структуру — vault не перестраиваем |
| Git-нативный синк | `vaultify status` · `sync [--dry]` | Per-vault стратегии `own / shared / none` вместо догмы «1 vault = 1 repo»; `status` показывает грязные и отставшие vault'ы, `sync` делает commit → pull --rebase → push по стратегии каждого |
| MCP-сервер | `vaultify mcp` | Локальный MCP-сервер (stdio JSON-RPC, без зависимостей) с 8 инструментами — поиск, memory save/handoff/resume, task add/list/move, vault status — агенты **любого** харнесса получают типизированный доступ без парсинга вывода CLI |
| Интеграции с харнессом | `vaultify integrations install zcode\|dsh` · `doctor` | Ставит скилл, слэш-команды, SessionStart-хук (доска + свежая память + грязные vault'ы в контексте) и вмерживает MCP-сервер в конфиг харнесса — с бэкапом; `doctor` проверяет разводку |
| Десктоп-компаньон | `vaultify-ui` | Приложение Tauri v2, доска-first: пять канбан-колонок с drag-and-drop, утренний resume-блок, поиск по vault'ам и статусы vault'ов — то же ядро в вебвью |

## Как это работает

Два слоя памяти — по паттерну LLM Wiki Карпатова:

1. **Сырой слой** — неизменяемый. Итоги сессий (`memory/sessions/S-NNNN.md`) и
   handoff'ы (`memory/handoffs/H-NNNN.md`) лежат обычным markdown в git-мета-репе
   `<install>/home/`. Пишутся через CLI в конце каждого значимого куска работы;
   задним числом не редактируются.
2. **Дистиллят** — живой. Ценные выводы становятся обычными заметками Obsidian
   в vault'ах пользователя, с провенансом во frontmatter
   (`source: vaultify/S-0042`) и `[[викилинками]]` на то, что уже есть.

**Канон — данные пользователя**: приложение владеет только мета-репой
(`<install>/home/`); снёс её — ничего своего не потерял. И канон один — vault'ы,
а не вики приложения. Запись в vault **детерминирована**: layout-профиль из
реестра маппит тип заметки на папку (незнакомые типы — во fallback-папку),
так что скилл решает, *чем* является заметка, но никогда — *куда* она падает.

```
VAULT'Ы ПОЛЬЗОВАТЕЛЯ (канон)                МЕТА-РЕПА <install>/home/ (владение приложения)
├── ~/Notes/Work    [git: own]              ├── config.*   ← настройки: реестр vault'ов,
├── ~/Notes/Life    [git: none]             │                 layout-маппинги, git-режимы
└── ~/Zettel        [git: shared]           ├── tasks.db   ← SQLite-реестр задач (канбан)
     ↑ дистиллят: агент пишет               ├── memory/    ← сырая память агентов (md):
       заметки по маппингу vault'а          │   sessions/  ← итоги сессий (источники)
       (никакой вики index/topics —         │   handoffs/  ← handoff-записи
       канон — vault'ы)                     └── index.db   ← производный индекс vault'ов
                                                                   (перестраиваемый, вне git)
```

В ядре **нет LLM**: индекс, поиск, доска и синк — детерминированный код.
Вся «интеллектуальность» — дистилляция, планирование, утренний флоу — живёт
в скиллах, исполняемых самим харнессом. Полная картина:
[docs/ru/architecture/overview.md](./architecture/overview.md).

## С чего начать

Сборка из исходников (Node ≥ 22.5 ради `node:sqlite`; Windows-first):

```
pnpm install
pnpm build          # → dist/
pnpm build:sea      # → dist/sea/vaultify.exe — один самодостаточный бинарь
```

**Где что лежит (развёртывание одной папкой):** положи `vaultify.exe` куда угодно
среди своих инструментов (например `D:/tools/vaultify/`) — `vaultify init` создаст
дом данных в `<эта папка>/home/`. Всё — бинари и данные — живёт в одной папке,
которую можно переносить и бэкапить целиком; `VAULTIFY_HOME` уводит данные в другое
место, если нужно.

Дальше разводка:

```
vaultify init                            # создаёт мета-репу <install>/home/
vaultify vault add ~/Notes/Work          # регистрирует vault (git-режим и layout — авто)
vaultify scan                            # строит поисковый индекс
vaultify search "квартальные цели"       # один поиск по всем vault'ам, задачам и памяти
vaultify integrations install zcode      # или: dsh — скилл, команды, хук, мерж MCP-конфига
vaultify doctor                          # проверяет разводку
```

Десктоп-компаньон: `pnpm ui` (dev-окно) или `pnpm ui:build` →
`vaultify-ui.exe`. Полная справка по командам: [docs/ru/cli-reference.md](./cli-reference.md).

## Решения

Семнадцать записанных решений формируют инструмент — полная таблица с
отклонёнными альтернативами в
[docs/ru/decisions/design-decisions.md](./decisions/design-decisions.md). Кратко:

| # | Решение |
|---|---|
| R1 | Стек как у devst: TypeScript, ноль runtime-зависимостей, SEA-бинарь, Tauri UI |
| R2 | Транспорт: CLI (SEA) + MCP поверх stdio + скиллы/хуки — **без демона** |
| R3 | Харнессы в v1: zcode + Claude Code, через адаптеры-инсталляторы + `doctor` |
| R4 | Без LLM в ядре; дистилляция и планирование — скиллы у харнесса |
| R5 | Канон знаний — **vault'ы пользователя**: не SQLite-канон, не вики приложения |
| R6 | Два слоя памяти: сырьё (сессии/handoff'ы) → дистиллят (заметки с провенансом) |
| R7 | Сырая память — markdown в git-мета-репе: человекочитаемо, git-история бесплатно |
| R8 | Задачи: SQLite-реестр с канбан-статусами `inbox/doing/waiting/someday/done` |
| R9 | Все данные приложения — в одной мета-репе `<install>/home/`: config, tasks.db, memory/, index.db |
| R10 | Git без догмы: per-vault стратегии `own`/`shared`/`none` + `status`/`sync` |
| R11 | Плоский мир: один глобальный поиск и одна доска; разделение тегами и фильтрами |
| R12 | Vault = любая папка с markdown; полировка — для Obsidian (frontmatter, викилинки) |
| R13 | Без гейтов и паролей — всё лежит открыто, осознанно |
| R14 | UI v1 — доска-first: канбан + утренний флоу; поиск в UI позже |
| R15 | Порядок сборки: фундамент → память → UI |
| R16 | Критерий готовности v1: утренний флоу e2e, одним дыханием |
| R17 | Запись в vault — через layout-профили: место записи детерминировано |

## Референсы

vaultify построен на явно названных идеях четырёх публичных проектов — всякий раз
с оговоркой, чем отличаемся:

| Референс | Что взято |
|---|---|
| [claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) | «Ты каптуришь — ИИ организует»: инбокс→заметки, `[[викилинки]]`, скиллы process/organize, отказ от RAG. В отличие от него, vaultify не строит «второй мозг приложения» — канон остаётся в vault'ах пользователя |
| [ai-memory](https://github.com/akitaonrails/ai-memory) | Общая память многих харнессов, handoff/resume-протокол, опыт install/doctor. В отличие от него, сырая память — markdown в git-репе, а не строки в SQLite |
| [Graphify](https://github.com/Graphify-Labs/graphify) | Идея детерминированного извлечения структуры — здесь frontmatter и викилинки вместо AST |
| [LLM Wiki (Карпатов)](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) | Паттерн двух слоёв: неизменяемые источники + живой, компаундящийся дистиллят с провенансом |

Сам метод сборки — TypeScript с чистым ядром, ноль runtime-зависимостей,
SEA-бинарь, Tauri-компаньон, installer + doctor — от
[devst](https://github.com/someguy3021/devst-public), проекта-сиблинга.

## Загрузка

Собранные бинари для Windows приложены к
[GitHub Releases](https://github.com/someguy3021/vaultify-public/releases):

- `vaultify.exe` — CLI + MCP-сервер (самодостаточный, Node не требуется)
- `vaultify-ui.exe` — десктоп-компаньон (нужен только WebView2, предустановлен
  в Windows 10/11)

Оба не подписаны — SmartScreen покажет предупреждение при первом запуске.
Исходный код не публикуется; см. [Статус и границы](#статус-и-границы).

## Статус и границы

vaultify — личный проект инструментария; этот репозиторий существует, чтобы
показать его проектный след и документацию. Явно о том, что это значит:

- **Исходный код не публичен**; бинари предоставляются как есть, без гарантий.
- Проект не ищет пользователей и контрибьюторов: ишью могут остаться без ответа,
  ломающие изменения — без объявления, поддержка не обещана.
- Проект **Windows-first** (SEA-бинарь + Tauri); кроссплатформенные сборки —
  работа будущего.
- Вывод и словарь CLI — по дизайну на **русском**: личный инструмент в обоих
  смыслах.

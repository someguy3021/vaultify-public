## Версия одним абзацем

vaultify — локальный инструмент общего назначения (не только кодинг), который
даёт всем ИИ-агентам пользователя три вещи: **общую память** (сессии, решения,
handoff'ы между харнессами), **общую канбан-доску** поверх SQLite-реестра и
**мета-управление и полнотекстовый-подобный поиск по нескольким Obsidian
vault'ам**. Это TypeScript с чистым ядром и нулём runtime-зависимостей (stdlib
Node, включая `node:sqlite`); всё, что касается внешнего мира, — файлы, git,
SQLite, процессы — живёт в тонких обвязках. Дистрибуция — один самодостаточный
бинарь (Node SEA) плюс десктоп-компаньон на Tauri v2, исполняющий то же ядро
в своём вебвью.

## Цель

Одно локальное приложение, которое всем ИИ-агентам пользователя (zcode,
Claude Code; позже — другие) даёт:

1. **Общую память** — сессии, решения, handoff'ы в одном месте, между харнессами.
2. **Общие задачи** — одна глобальная доска (канбан) поверх SQLite-реестра;
   двигают и человек, и агенты.
3. **Мета-управление хранилищами и поиск** — несколько Obsidian vault'ов (и
   любых md-папок; фокус — Obsidian): единый индекс, префиксный
   полнотекстовый-подобный поиск, дистилляция знаний агентом прямо в vault'ы.

### Не-цели (осознанно не делаем)

- RAG/эмбеддинги, векторные базы, облако, серверы (демона нет — CLI/MCP на stdio).
- Пароли, шифрование, гейты доступа агентов (всё лежит открыто — решение автора).
- Пространства/домены с раздельными правами (плоский мир).
- Типизированные сущности (Project/Person/…) — плоский md-граф.
- Канон знаний в собственной базе приложения (SQLite-канон отклонён).

## Принципы

- **Канон — данные пользователя.** Знания — в vault'ах; сырая память агентов —
  md в мета-репе. Приложение = индекс + поиск + доска + транспорт; всё его
  владение — мета-репа.
- **Ядро без LLM.** Индекс, поиск, доска, синк — детерминированный код;
  интеллект — скиллы у харнесса. Ноль API-ключей.
- **Git-нативно.** Мета-репа — git; vault'ы — per-vault стратегии
  `own`/`shared`/`none`, мета-команды `status`/`sync` работают поверх любых
  комбинаций.
- **Zero runtime-deps, SEA, Tauri** — метод сборки
  [devst](https://github.com/someguy3021/devst-public).
- **Пишем в vault'ы только по маппингу из реестра** (layout-профили) — не по
  воле скилла.

## Слои данных

```
VAULT'Ы ПОЛЬЗОВАТЕЛЯ (канон)                МЕТА-РЕПА <install>/home/ (владение приложения)
├── ~/Notes/Work    [git: own]              ├── config.*   ← настройки: реестр vault'ов,
├── ~/Notes/Life    [git: none]             │                 layout-маппинги, git-режимы
└── ~/Zettel        [git: shared]           ├── tasks.db   ← SQLite-реестр задач (канбан)
     ↑ дистиллят: агент пишет               ├── memory/    ← сырая память агентов (md):
       заметки по маппингу vault'а          │   sessions/  ← итоги сессий (источники)
       (никакой вики index/topics —         │   handoffs/  ← handoff-записи
       канон — vault'ы)                     └── index.db   ← производный индекс vault'ов
                                                                   (перестраиваемый, вне git)
```

Инвариант: **два слоя памяти** (паттерн LLM Wiki Карпатова). Сырьё (сессии,
handoff'ы) — неизменяемое, в мета-репе; дистиллят (выводы, выжимки) — живые
заметки в vault'ах, каждая с провенансом — frontmatter-ссылкой на
сессию-источник (`source: vaultify/S-NNNN`).

## Компоненты

| Компонент | Что | Транспорт |
|---|---|---|
| **CLI `vaultify`** | `init`, `vault add/list/show/rm/map`, `scan`, `search`, `status`, `sync`, `task …`, `memory …`, `mcp`, `integrations install`, `doctor` | SEA-бинарь |
| **MCP-сервер** | 8 инструментов: `vault_search`, `memory_save`, `handoff`, `resume`, `task_list`, `task_add`, `task_move`, `vault_status` | stdio; тот же бинарь в режиме `mcp` |
| **Скиллы + хуки** | Дистилляция, утренний флоу, поиск-этикет; SessionStart-хук подаёт состояние (доска, свежая память, грязные vault'и) в контекст | адаптеры: zcode, Claude Code (`dsh`) |
| **Tauri UI** | Доска-first: канбан с drag-and-drop, утренний флоу; управление vault'ами; поиск | отдельное десктоп-приложение |

Чистые модули ядра (`src/*.ts`, без `node:*`): утилиты аргументов, парсинг
markdown (frontmatter / викилинки), layout-профили с авто-детектом, реестр
vault'ов, план скана/ранжирования/сниппетов, ядро канбана, форматы памяти.
Обвязки (`*-run.ts`): мета-репа (`<install>/home/`, env `VAULTIFY_HOME`),
SQLite-инверт-индекс, git-стратегии (детект `own`/`shared`/`none`,
`status`/`sync` с автокоммитом и `pull --rebase`), база канбана, файлы памяти,
MCP stdio-сервер, integrations install/doctor.

## Потоки

- **Утренний флоу:** «что делать сегодня?» → скилл читает доску (P0/P1,
  протухание) + свежую память + статусы vault'ов → предлагает 1–3 задачи
  с контекстом.
- **Сессия с агентом:** в конце — `memory_save` (итог сессии →
  `memory/sessions/`) и/или `handoff` (сделано / осталось / грабли →
  `memory/handoffs/`). Другой харнесс подбирает через `resume`.
- **Дистилляция:** скилл периодически (или по запросу) читает сырые сессии →
  пишет выводы заметками в vault'ы по layout-маппингу, с провенансом.
- **Поиск:** CLI/MCP → префиксный полнотекстовый-подобный запрос по
  производному индексу vault'ов + задачам + памяти.
- **Синк:** `vaultify status` (грязные / отставшие) → `vaultify sync`
  (commit+pull+push по git-стратегии каждого vault'а и мета-репы).

## Критерий готовности v1

**Утренний флоу e2e, одним дыханием:** утром агент видит доску и память →
предлагает план → работает → в конце сессии handoff → дистиллят появился
в vault'е → поиск находит и старое, и новое. UI — часть критерия.

## Референсы

| Референс | Что заимствовано |
|---|---|
| **devst** ([публичная репа](https://github.com/someguy3021/devst-public)) | Метод сборки: TS / zero-deps / SEA / Tauri, `integrations install` + `doctor`, ADR-процесс, реестр задач, дисциплина доков |
| [claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) | «Ты каптуришь — ИИ организует»: инбокс→заметки, `[[викилинки]]`, скиллы process/organize; отказ от RAG |
| [ai-memory](https://github.com/akitaonrails/ai-memory) | Общая память многих харнессов, handoff/resume-протокол, опыт install/doctor |
| [Graphify](https://github.com/Graphify-Labs/graphify) | Идея детерминированного извлечения структуры (у нас — frontmatter/викилинки вместо AST) |
| [LLM Wiki (Карпатов)](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) | Два слоя: неизменяемые источники + живой дистиллят с провенансом; поиск обходом, не векторами; вики компаундится |

Ключевое отличие от каждого: vaultify не строит «второй мозг приложения» (как
claude-obsidian или LLM Wiki) — канон остаётся в vault'ах пользователя; и не
строит память-базу (как ai-memory) — сырая память это markdown в git-мета-репе.

## Layout-профили (R17 подробнее)

На каждый vault в реестре — **маппинг «тип заметки → папка»**; скилл читает его
(`vaultify vault show <имя> --json`) и пишет строго по маппингу. *Тип* заметки
(журнал / проект / концепт / …) выбирает скилл — это интеллект; *место*
детерминировано — это ядро. Незнакомый тип — в `fallback`-папку.

| Пресет | Поведение |
|---|---|
| `strict` | Жёсткая структура по типам (в духе claude-obsidian). Для vault'ов, где хочется машинного порядка |
| `flex` (дефолт) | При `vault add` авто-детект существующих папок верхнего уровня (Journal/Diary→journal, Projects→projects, Sources, People, Concepts…, со словарём RU/EN-синонимов) и карта из того, что есть. Vault не перестраиваем |
| `single` | Всё от агента — в одну папку `Vaultify/` |

Сопровождение: `vaultify vault map <имя>` — пересмотреть маппинг руками.

## Отклонённые альтернативы

Решения выше приняты против явных альтернатив, каждую стоит назвать:

- **SQLite-канон знаний.** Структурированное хранилище как источник истины
  создало бы двойную истину с Obsidian-vault'ами, которые пользователь уже
  ведёт. Канон должен быть один — и это vault'ы.
- **Вики приложения** (`~/vaultify/wiki/` с дистиллированными заметками, как у
  claude-obsidian или LLM Wiki). То же возражение: рядом с первым мозгом
  пользователя вырос бы второй. Дистиллят уходит в vault'ы.
- **Пространства / домены с правами.** Типизированные пространства и раздельный
  доступ добавили бы модель прав в локальный однопользовательский инструмент.
  Плоский мир: один глобальный поиск и одна доска, разделение тегами и фильтрами.
- **TTL-гейт / пароли.** Доступ по времени и гейты для агентов — из другой
  модели угроз, другого проекта. vaultify держит всё открытым — явное решение
  автора.
- **Демон.** localhost-сервис (путь ai-memory) — это процесс под присмотром,
  порты, второй рантайм. CLI (SEA) + MCP поверх stdio + скиллы закрывают ту же
  поверхность, и присматривать не за чем.
- **RAG / эмбеддинги / векторные базы.** Поиск здесь — префиксный инверт-индекс
  на `node:sqlite` (осознанно без FTS5) плюс обход ссылок — детерминированно,
  перестраиваемо, ноль API-ключей.
